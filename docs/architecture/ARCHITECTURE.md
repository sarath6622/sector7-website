> Last updated: 2026-03-09

## Tech Stack

| Layer | Technology | Notes |
|---|---|---|
| Framework | Next.js 16.1.6 | App Router, Server Components by default |
| Language | TypeScript | strict: true, zero `any` types |
| Styling | Tailwind CSS v4 + CSS custom properties | Color tokens defined as CSS variables |
| Animations | Framer Motion | Page transitions, scroll reveals, micro-interactions |
| Icons | Lucide React | — |
| Forms | React Hook Form + Zod | Client-side validation + server-side Zod parsing |
| CMS | Sanity.io | Headless, GROQ queries, webhook-based ISR revalidation |
| Image Handling | Next.js Image + Sanity CDN | AVIF/WebP, blur-up placeholders |
| Analytics | GA4 + Microsoft Clarity | Custom events, heatmaps, session recordings |
| SEO | next-sitemap + JSON-LD | Structured data on all pages |
| WhatsApp | Click-to-chat API | Contextual prefilled messages, no backend required |
| Deployment | Vercel | Edge Functions for API routes, ISR |
| Email | Resend | Form submission notifications |

## Data Flow

```
Browser → Next.js App Router
  ├── Server Components → fetch from Sanity (server-side, cached with ISR)
  │     └── revalidation triggered by Sanity webhook → /api/revalidate
  ├── Client Components → Framer Motion, React Hook Form, browser APIs
  └── API Routes → form submissions → Resend (email) + validation + rate limiting
```

## SEO Architecture

> Added: Phase 10 (2026-03-09)

### Metadata strategy

Every page exports a `metadata` object. Static pages use the `generateMetadata()` helper from `src/lib/seo.ts` which automatically populates:
- `<title>` (with `%s | Sector 7 Gym Kochi` template from root layout)
- `<meta name="description">`
- `<link rel="canonical">`
- `og:title`, `og:description`, `og:image`, `og:url`, `og:type`
- `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`

Dynamic pages (`/trainers/[slug]`, `/blog/[slug]`) use `async generateMetadata()` to fetch real data from Sanity before generating tags.

### JSON-LD structured data

JSON-LD is rendered as `<script type="application/ld+json">` directly in page JSX — never in `<head>`.

| Location | Schema | Key properties |
|---|---|---|
| Root layout (`layout.tsx`) | `LocalBusiness` | name, address, geo, telephone, openingHours |
| Homepage (`page.tsx`) | `WebSite` + `SearchAction` | Enables sitelinks search box signal |
| `/trainers/[slug]` | `Person` | name, jobTitle, worksFor, image, hasCredential |
| `/blog/[slug]` | `Article` | headline, author, publisher, image, datePublished |
| `/pricing` | `FAQPage` | All FAQ question/answer pairs |
| `/pricing` | `Product` + `Offer` | One per membership plan, with price in INR |

All JSON-LD is generated via `generateJSONLD()` from `src/lib/seo.ts`.

### Sitemap

Generated automatically by `next-sitemap` as a **postbuild** script (`npm run build` → `next-sitemap`).

Output: `public/sitemap.xml` (index) + `public/sitemap-0.xml` (entries)

Config: `next-sitemap.config.js` — excludes `/api/*` and `/studio/*`, sets per-page priority and changefreq.

After deploying, submit `https://sector7gym.com/sitemap.xml` to Google Search Console.

### Analytics scripts

Both scripts are loaded via `next/script` with `strategy="afterInteractive"` — they never block rendering.

- **GA4** (`GoogleAnalytics` component): loads if `NEXT_PUBLIC_GA_MEASUREMENT_ID` is set. Silent no-op otherwise.
- **Microsoft Clarity** (`MicrosoftClarity` component): loads if `NEXT_PUBLIC_CLARITY_PROJECT_ID` is set. Silent no-op otherwise.
- Both are rendered at the bottom of `<body>` in `layout.tsx`.
- GA4 events must go through `trackEvent()` in `src/lib/analytics.ts` — never call `gtag()` directly.

## Security Architecture

- HTTPS enforced (Vercel default)
- CSP headers in `next.config.ts`
- Rate limiting on `/api/contact`, `/api/newsletter` (3 req/IP/hour)
- Honeypot fields on all public forms
- Server secrets never prefixed with `NEXT_PUBLIC_`
- All user inputs sanitized server-side before email dispatch
